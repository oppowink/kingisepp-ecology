# ЭкоБиоМониторинг

Полный архив исходников от 4 октября 2026 года, версия 0.2.0. Включает обе части обновления. Опубликованный сайт и настоящая база этим архивом не изменены. Серверных функций по-прежнему восемь.

## Что работает в этой сборке

Сохранён узнаваемый стиль, добавлены розовые шапка и виньетка, чередование карточек, анимация логотипа и значков. Переработаны игры, кабинеты и мобильные формы. Обучение можно повторить. Первые три секунды урок нельзя пролистать.

Заявка заполняется последовательно. Сначала участник видит правила фотографирования и единый код заявки, затем паспорт точки. Для каждого из 2–5 деревьев загружаются обзорное фото с кодом и 10–30 отдельных фотографий листьев без кода. Разное количество листьев допускается. Проверка формата, разрешения и светлого фона происходит до разметки.

На каждом листе ставятся 12 синих ориентиров. Пять пар признаков дают ФА листа; листья усредняются по дереву, деревья по точке с одинаковым весом. Максимум 150 листьев. Расчёт не подменяет инструментальное измерение загрязнения. PDF содержит результаты по листьям, деревьям и точке, формулу и условные уровни асимметрии.

Модератор проверяет фотографии, паспорт и все ориентиры, может поправить их касанием или клавиатурой. После изменения разметки требуется повторное одобрение и расчёт. PDF доступен также в кабинете модератора. На карте сохранены 18 исходных авторских точек.

У организации есть адрес и электронная почта. Куратор задаёт центр и радиус или контур территории, выбирает участника своей организации. Исправлена передача идентификатора при назначении. Для проверки нужны разные аккаунты куратора и участника.

Сертификаты волонтёра, модератора и куратора скачиваются в PDF после подтверждения результата обучения сервером. Это сертификаты модуля проекта, без выдуманных подписей и статуса документа о квалификации. В демонстрационном режиме стоит отметка «ОБРАЗЕЦ». Неудачная повторная попытка теста сохраняет ранее полученный допуск.

Помощник доступен на страницах. Есть поиск по справке и выбор фрагмента страницы для вопроса. Подключение Yandex AI Studio подготовлено, но без настройки работает только локальная справка. Классификатор вида листа не подключён. Его отсутствие не маскируется проверкой белого фона.

## Установка поверх существующей версии

1. Сохраните копию репозитория и базы. Временно не принимайте новые заявки во время обновления.
2. Если миграции 001–007 уже выполнены, выполните 008, затем 009 и 010. Если уже установлена первая часть с 008, начинайте с 009. Повторно запускать 001–007 не нужно.
3. Замените файлы проекта содержимым папки `site` из архива. Корнем проекта в Vercel должна быть именно эта папка, содержащая `package.json`, `index.html` и `api`.
4. Сохраните существующие переменные Supabase. SESSION_SECRET должен содержать минимум 32 случайных символа; его замена завершит старые сеансы. APP_URL должен соответствовать адресу сайта. ASSISTANT_ENABLED оставьте false, пока не настроены модель и лимит.
5. Разверните обновление. Затем выполните 011_private_photos.sql. Она закрывает бакет monitoring-photos и прямые обращения к нему через anon/authenticated. Старые публичные ссылки на фото перестанут открываться; файлы не удаляются. Новый сервер выдаёт временные ссылки сроком на час после проверки доступа. До выполнения 011 бакет остаётся публичным.
6. Проверьте два аккаунта: участник подаёт заявку, модератор проверяет, рассчитывает ФА и публикует. Проверьте организацию и назначение территории. Скачайте сертификат и PDF расчёта.

Для новой базы порядок: 001_profiles.sql, затем файлы 002–011 по порядку. 001_users.sql оставлен как историческая альтернативная схема; после 001_profiles.sql он не нужен. Исправлена ошибка ограничения статусов в 006, которая мешала новой установке.

Обновлённый сервер требует миграцию 010: если таблица лимитов недоступна, запись блокируется, а не разрешается без защиты. Функция атомарного сохранения использует таблицу monitoring_requests. Нестандартное имя SUPABASE_REQUEST_TABLE для этой сборки не поддерживается.

Если старый профиль не связан с Supabase Auth, автоматической привязки только по почте больше нет. Владелец базы должен проверить принадлежность аккаунта и установить правильный supabase_auth_id. Не выдавайте повышенную роль для обхода этой проверки.

## Как включить нейросетевого помощника

Сначала выполните 009. В настройках окружения Vercel укажите YANDEX_API_KEY, YANDEX_FOLDER_ID, YANDEX_TEXT_MODEL и положительный ASSISTANT_DAILY_REQUEST_LIMIT. Значение модели берётся из вашей консоли AI Studio: можно указать полный URI gpt://… или имя с версией. После этого установите ASSISTANT_ENABLED=true и сделайте redeploy. Для вопросов по фото требуется отдельная поддерживающая изображения модель в YANDEX_VISION_MODEL.

Ключ хранится только на сервере. Вопрос и выделенный фрагмент отправляются после согласия. Внешний вызов ограничен по времени и бюджету. При недоступности модели интерфейс возвращается к справке. Реальный вызов с вашим ключом не проверен.

Официальная инструкция подключения: https://aistudio.yandex.ru/ru/docs/ai-studio/operations/generation/completions-basic

Для классификатора нужны обученные веса, порядок классов, размер и способ подготовки входного изображения, версия модели и результаты независимой проверки. Найденный ноутбук обучения не заменяет эти файлы. ФА считается независимо от классификатора.

## Защита и её пределы

Сервер получает текущую роль из базы, проверяет владельца заявки и право на действие. Ограничены формат и размер JSON, происхождение запросов, типы и размеры загрузок. Проверяется наличие фото в Storage. Заявка и хеши теперь сохраняются одной транзакцией: конфликт не оставляет неполную запись.

После миграции 011 проверочные фото доступны только через разрешённую заявку; публичная карта получает лишь выбранные фото листьев. Временная ссылка доступна любому, кому её передали, до истечения часа. Загрузка фото с лицами и документами не требуется.

Лимиты: 30 попыток входа с одного адреса за 10 минут, 60 на одну почту за час, 5 регистраций с адреса за час, 5 сообщений обратной связи за час, 500 разрешений на загрузку файлов в сутки на участника, 120 операций изменения за 10 минут. Это фиксированные временные окна. Общая школьная сеть может разделять лимит IP. IP и почта для счётчика хранятся как HMAC, а не открытым текстом.

Проверка хешей и размеров не доказывает подлинность фотографий. Хеш передаётся клиентом, код и вид дерева проверяет человек. Подтверждение электронной почты пока автоматически, как в исходной регистрации. Полная CSP для внешней карты не настроена. Неиспользованные после ошибок загрузки файлы требуют отдельного обслуживания. Полного аудита инфраструктуры Supabase/Vercel без доступа к ней не проведено.

## Проверки

В комплекте автоматические проверки расчётов, ролей, входа, помощника, обратной связи и временных ссылок. SQL проверяется локально в PGlite на отдельной схеме с имитацией системных таблиц Supabase. Это не проверка живого сервиса Storage.

```bash
npm ci
npm test
npm run test:db
npm run check
```

В Chromium проверены мобильная и настольная вёрстка, форма с 55 листьями и 660 касаниями, PDF, повторное обучение, сертификаты, выбор фрагмента помощником, обратная связь и назначение участника. Внешние сервисы и запись пользовательских данных в браузерных проверках заменялись тестовыми ответами. Safari на физическом iPhone и настоящая Яндекс Карта требуют проверки после установки.

Открытие index.html с диска не запускает сервер. Для работы аккаунтов, организаций, сохранения данных и обучения нужен Vercel с настроенным Supabase.
