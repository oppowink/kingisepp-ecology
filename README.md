# ЭкоБиоМониторинг

Статический фронтенд и Vercel Functions для Supabase.

## Регистрация без почтового кода

Регистрация выполняется по e-mail и паролю. Серверная функция создаёт подтверждённого пользователя через Supabase Admin API, поэтому SMTP для первого входа не требуется. Секретный ключ используется только внутри Vercel Functions.

Пароль при регистрации должен содержать минимум 8 символов, заглавную и строчную буквы, цифру и спецсимвол. Повтор пароля проверяется на фронтенде и на сервере.

Перед деплоем добавьте в Vercel переменные из `.env.example`:

- `SUPABASE_URL`;
- `SUPABASE_PUBLISHABLE_KEY` или `SUPABASE_ANON_KEY`;
- `SUPABASE_SECRET_KEY` или `SUPABASE_SERVICE_ROLE_KEY`;
- `SESSION_SECRET`, случайная строка длиной не менее 32 символов;
- `APP_URL`, адрес опубликованного сайта.

В Supabase SQL Editor по порядку выполните:

1. `supabase/001_profiles.sql`
2. `supabase/002_learning_and_certificates.sql`
3. `supabase/003_monitoring_requests.sql`
4. `supabase/004_feedback_messages.sql`
5. `supabase/005_organizations_curators_and_passports.sql`

Таблица профилей называется `profiles`. Поле `role` в ней определяет, кто видит модерацию и админ-панель.
Вторая миграция добавляет прогресс обучения, сертификаты и поля статуса обучения в профиль.
Третья миграция добавляет заявки с двухэтапной модерацией.
Четвёртая миграция добавляет сообщения обратной связи.
Пятая миграция добавляет роль куратора, организации, проекты, объекты, назначения, паспорт территории, паспорт дерева и bucket `monitoring-photos`.

Серверный secret/service-role ключ нельзя добавлять в HTML, клиентский JavaScript или переменные с префиксом `PUBLIC`.

## Что уже подключено

- обучение волонтёра из 6 шагов и теста на 7 вопросов;
- сохранение статуса обучения локально и через `/api/education/complete`, если доступен Vercel API;
- блокировка добавления точки до прохождения обучения;
- сертификат волонтёра-исследователя через печатную страницу браузера;
- админский блок в `moderator.html`: статистика заявок, назначение ролей, выдача роли куратора и блокировка пользователей;
- двухэтапная модерация: сначала решение человека, затем заглушка проверки нейросетью, после этого публикация на карте;
- обучение и тест модератора на отдельной странице;
- кабинет куратора: организация → проект → объект → назначение участнику;
- подключение участника к организации по коду и поле города в профиле;
- выбор координат дерева на карте без ручного ввода;
- паспорт территории, обязательное фото берёзы и 30 фото листьев;
- подписанная загрузка фотографий прямо в Supabase Storage через существующую функцию `/api/requests/list`;
- страницы «О проекте и авторе» и «Передохни: экологический детектив»;
- три подготовленных места под агитационно-просветительские ролики на главной.

Методичка куратора лежит в `docs/curator-method-guide.pdf`; редактируемая версия — в `docs/curator-method-guide.docx`.

## Структура полевых данных

`Организация → проект → объект/территория → точка → одно дерево → 30 листьев`.

Одна заявка всегда описывает одну точку и одно дерево. Куратор организует задания и видит статусы своей группы, но не принимает научное решение по заявке: это отдельная роль модератора.

## Ограничение Vercel Hobby

Новых файлов в `/api` для функций организаций и загрузки фото не добавлено. В проекте остаётся 8 serverless functions; новая логика объединена с `/api/requests/list`.
